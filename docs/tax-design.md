# 飞税税务管理系统 · 建设方案

**版本**：v1.0　**日期**：2026-10　**密级**：内部
**口径基准**：《中华人民共和国增值税法》（2026-01-01 施行）及现行税收优惠政策

---

## 1. 项目背景与目标

### 1.1 背景

集团下属 8 家纳税主体，覆盖软件、制造、商贸、建筑、咨询、文化、物流、新能源八大行业，纳税人身份横跨一般纳税人与小规模纳税人。当前税务工作存在以下痛点：

- **数据分散**：发票、申报、凭证分别在不同系统或线下 Excel，集团层面无法一屏总览；
- **口径不统一**：各主体自行套用税率与优惠政策，税收口径（如六税两费减半、小微 5%）执行有偏差；
- **风险滞后**：三流不一致、税负异常等问题在税务检查时才暴露，缺乏事前预警；
- **对接困难**：与 ERP、财务核算系统无标准接口，月末对账靠人工导出导入。

### 1.2 建设目标

| 目标 | 度量 |
| --- | --- |
| 全税种一平台 | 增值税、附加税费、企业所得税、个人所得税、印花税、房产税、城镇土地使用税等 8 大税种统一管理 |
| 计算零误差 | 计算内核全部基于 Decimal 精确十进制，杜绝浮点误差 |
| 申报全流程 | 试算 → 填报 → 申报 → 缴款 → 凭证，闭环留痕 |
| 风险前置 | 内置规则引擎，扫描三流不一致、税负偏离、进项转出缺失等 7 类信号 |
| 开放对接 | 54 个 REST 接口 + OpenAPI 3.0 描述 + 增量同步协议，预留 ERP / 财务 / 资金系统对接 |

### 1.3 设计原则

1. **零依赖部署**：仅 Python 3.9+ 标准库（http.server + sqlite3），无 pip install，单机即可运行；
2. **纯函数内核**：税法计算（`tax.py`）不碰数据库、无 IO，可独立单元测试；
3. **统一响应包**：`{code, message, data}`，code 与 HTTP 状态码一致；
4. **权限最小化**：6 角色 × 细粒度权限点，接口级强制校验；
5. **幂等与增量**：写接口支持 `Idempotency-Key`，读接口支持版本号增量同步。

## 2. 税种口径（政策依据）

### 2.1 增值税

- **法定税率**：13% / 9% / 6% / 0%（销售、进口货物与服务适用）；
- **征收率**：3%（2026 年起取消 5%）；
- **小规模优惠**：月销售额 ≤10 万元（季 ≤30 万元）免征；超过起征点的，3% 征收率**减按 1%**（政策延续至 2027-12-31，不含销售/出租不动产、转让土地使用权）；
- **一般计税**：应纳税额 = 销项税额 −（进项税额 + 上期留抵 + 加计抵减 − 进项转出），不足抵扣部分形成期末留抵。

### 2.2 附加税费（随增值税征收）

| 税费 | 市区 | 县城/镇 | 其他 |
| --- | --- | --- | --- |
| 城建税 | 7% | 5% | 1% |
| 教育费附加 | 3% | 3% | 3% |
| 地方教育附加 | 2% | 2% | 2% |

小型微利企业 / 小规模纳税人享受**六税两费减半**（2023-01-01 ~ 2027-12-31），月销售额 ≤10 万元免征教育费附加、地方教育附加。

### 2.3 企业所得税

- 基本税率 25%，高新技术企业 15%；
- 小型微利企业（应纳税所得额 ≤300 万、从业 ≤300 人、资产 ≤5000 万）：减按 25% 计入 × 20% = **实际税负 5%**；
- 支持纳税调增 / 调减、弥补以前年度亏损、研发费用加计扣除。

### 2.4 个人所得税

综合所得七级超额累进（年）：

| 应纳税所得额 | 税率 | 速算扣除数 |
| --- | --- | --- |
| ≤36,000 | 3% | 0 |
| 36,000 ~ 144,000 | 10% | 2,520 |
| 144,000 ~ 300,000 | 20% | 16,920 |
| 300,000 ~ 420,000 | 25% | 31,920 |
| 420,000 ~ 660,000 | 30% | 52,920 |
| 660,000 ~ 960,000 | 35% | 85,920 |
| >960,000 | 45% | 181,920 |

工资薪金应纳税所得额 = 年收入 − 6 万基本减除 − 三险一金 − 专项附加扣除 − 其他扣除。
全年一次性奖金（2023 年第 30 号公告，至 2027-12-31）：可单独计税（÷12 查按月表）或并入综合所得，系统自动比较择优。

### 2.5 印花税（17 税目 5 档）

| 档位 | 税率 | 税目 |
| --- | --- | --- |
| 万分之零点五 | 0.005% | 借款合同、融资租赁合同 |
| 万分之三 | 0.03% | 买卖、承揽、建设工程、运输、技术合同、知识产权转让 |
| 千分之一 | 0.1% | 租赁、保管、仓储、财产保险合同、证券交易 |
| 万分之五 | 0.05% | 产权转移、股权转让书据 |
| 万分之二点五 | 0.025% | 营业账簿 |

计税依据默认不含增值税（合同单独列明增值税的）。

### 2.6 房产税 / 城镇土地使用税

- 房产税从价：应税原值 ×（1−10%~30% 减除）× 1.2%/年；从租：租金 × 12%；
- 城镇土地使用税：按土地等级 1.5 ~ 30 元/㎡·年（系统 6 级可配）。

### 2.7 滞纳金

自滞纳之日起按日加收滞纳税款的**万分之五**（税收征管法第 32 条）。

## 3. 总体架构

```
┌────────────────────────────────────────────────┐
│  前端 SPA（原生 JS，无框架）                       │
│  工作台 / 发票 / 进项 / 申报 / 计算器 / 税负分析      │
│  风险预警 / 主体 / 凭证 / 政策库 / 系统管理          │
├────────────────────────────────────────────────┤
│  服务层 server.py（54 路由，ThreadingHTTPServer）   │
│  统一响应 {code,message,data} · 鉴权五通道          │
│  幂等 Idempotency-Key · 增量同步 · CSV 导出          │
├──────────────────────┬─────────────────────────┤
│  税计算内核 tax.py     │  数据层 db.py             │
│  纯函数 · Decimal      │  SQLite WAL · 19 表       │
│  10 类税种 + 风险规则   │  8 索引 · 版本号同步       │
└──────────────────────┴─────────────────────────┘
        ↑ 外部系统：ERP / 财务核算 / 资金 / 开票
          REST + API Key + 增量同步
```

### 3.1 技术选型

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | 原生 JS SPA + hash 路由 | 无构建链，11 页面单页应用 |
| 服务 | http.server.ThreadingHTTPServer | 多线程，零依赖 |
| 数据 | SQLite WAL 模式 | 单文件库，支持并发读 |
| 计算 | decimal.Decimal | 精确到分，四舍五入 ROUND_HALF_UP |
| 鉴权 | Token（SHA-256 存储）+ API Key | 五通道，权限通配 |

### 3.2 数据模型（19 表）

| 分组 | 表 | 说明 |
| --- | --- | --- |
| 组织 | depts, users, tokens, api_keys | 部门 / 用户 / 令牌 / 接口密钥 |
| 主体 | entities | 8 家纳税主体，含小微、高新标识 |
| 发票 | invoices, invoice_items | 销项/进项台账与明细行 |
| 申报 | declarations, tax_types | 112 张申报单、8 大税种 |
| 凭证 | vouchers, contracts | 涉税凭证、合同与印花税 |
| 风险 | risks | 险/警/提三级风险信号 |
| 政策 | policies, notices | 法规库、公告 |
| 支撑 | logs, idem_keys, sync_state, tax_rules | 审计、幂等、同步、参数 |

## 4. 核心功能设计

### 4.1 发票管理

- 销项 / 进项统一台账，专票 / 普票 / 电子发票；
- 新增开票自动算税（含税 / 不含税双口径）；
- 进项发票勾选认证（校验销方税号、作废状态）；
- **三流一致校验**：发票流（开票双方）、合同流（合同签订方与金额）、资金流（付款方）交叉比对，不一致自动出「险」级信号；
- 单张发票作废留痕。

### 4.2 纳税申报

状态机：`草稿 → 待申报 → 已申报 → 已缴款`（不可逆，已申报后禁止删除）。

1. **试算**：按主体 + 税种 + 期间从发票、工资等源数据自动算出计税依据与应纳税额；
2. **填报**：保存为申报单，可人工调整；
3. **申报**：锁定单据，记录申报时间与期限；
4. **缴款**：登记缴款并**自动生成会计凭证**（借：应交税费 / 贷：银行存款）；
5. **逾期预警**：申报期限前 N 天提醒（N 可配），逾期标红。

### 4.3 税种计算器

13 个计算模型即时试算（不入库）：增值税单票 / 小规模 / 一般计税、附加税费、企税年度 / 季度、个税综合 / 工资 / 年终奖、印花税（单笔 / 批量）、房产税、土地使用税、综合税负率、滞纳金。入参兼容 snake_case 与 camelCase。

### 4.4 税负分析

- **综合税负率** = 税额合计 ÷ 营业收入；
- 按主体、按税种两个维度的税额排行与占比；
- 近 6 期销项 / 进项 / 申报趋势图；
- 进项税率结构、认证状态、供应商集中度 Top10；
- **税负偏离预警**：与行业均值偏离超容差（默认 30%）出「警」级信号。

### 4.5 风险预警

内置规则引擎（可扩展）：

| 规则码 | 等级 | 说明 |
| --- | --- | --- |
| CONTRACT_MISMATCH | 险 | 进项发票金额与合同金额不一致 |
| BURDEN_LOW / BURDEN_HIGH | 警 | 税负率偏离行业均值超容差 |
| INPUT_TRANSFER | 警 | 购进用于集体福利/免税项目未做进项转出 |
| INV_NO_TAX_NO | 警 | 进项专票销方税号为空，不得抵扣 |
| CITY_RATE_MISMATCH | 提 | 城建税适用税率与注册地不符 |
| INVOICE_OVER_LIMIT | 提 | 单张发票金额超上限 |
| DECL_OVERDUE | 险 | 申报逾期 |

每条信号带权重，汇总为 0~100 风险指数（≥70 高 / ≥40 中 / >0 低），支持处置与忽略留痕。

### 4.6 政策库

现行有效法规汇编（增值税法、六税两费、年终奖、印花税法等 8 篇起步），支持按税种 / 关键词检索，附税率速查卡。

## 5. 安全与权限

### 5.1 鉴权五通道

```
1. Authorization: Bearer <token>
2. X-Tax-Token: <token>
3. Cookie: tax_token=<token>
4. ?token=<token>          （文件导出等场景）
5. X-Tax-Key: <api key>    （系统对接）
```

Token 与 API Key 均以 SHA-256 摘要落库，泄库不泄密。

### 5.2 角色矩阵（6 角色）

| 角色 | 典型权限 |
| --- | --- |
| admin 系统管理员 | *（全部） |
| manager 管理层 | 查询 + 申报审批 + 报表 |
| tax_accountant 税务会计 | 开票 / 认证 / 转出 / 申报 / 凭证 |
| finance 财务会计 | 发票认证 + 报表 |
| auditor 内审 | 只读全业务 |
| reader 报表使用者 | 只读报表与政策 |

权限点形如 `invoice.write`、`tax.declare`，支持 `*`（全权）与前后缀匹配；接口级强制校验，越权返回 403。

### 5.3 审计

登录、开票、认证、申报、缴款、参数修改、密钥创建等全部动作落 `logs` 表（操作人 / 动作 / 对象 / 详情 / IP）。

## 6. 对外集成（预留）

- **协议**：REST + JSON，OpenAPI 3.0 描述文档（`GET /api/apidoc` 可直接导入 Postman / Apifox）；
- **对接通道**：API Key 鉴权（read / write / full 三档作用域）；
- **增量同步**：`GET /api/sync/version` 取各实体当前版本号，`GET /api/sync?version=invoices:35&entities=invoices,declarations` 只拉取变化数据；
- **幂等**：写接口携带 `Idempotency-Key` 头，重复请求返回首次结果；
- **导出**：发票 / 申报 CSV（UTF-8 BOM，Excel 直开不乱码）。

典型对接场景：

| 场景 | 链路 |
| --- | --- |
| ERP 采购发票自动入池 | ERP → POST /api/invoices/save（Idempotency-Key=ERP 单号） |
| 财务系统取申报数据 | 财务 → GET /api/sync?entities=declarations 定时拉增量 |
| 资金系统获取待缴清单 | 资金 → GET /api/declarations?status=已申报 |
| 集团报表合并 | BI → GET /api/reports/summary（一次取四块） |

## 8. 部署形态

- **端口**：8024（与 OA 8023、APS 8022 等并存）；
- **反向代理**：nginx `location /tax/` → 127.0.0.1:8024；
- **进程守护**：systemd 单元 `feishui-tax.service`，异常自动重启；
- **数据备份**：SQLite 单文件 `data/feishui.db`（WAL 模式），可直接 cron 复制；
- **环境变量**：`TAX_PORT`（端口）、`TAX_DB`（库路径）、`TAX_PREFIX`（子路径部署）。
